# AdPulse – Publisher Revenue & Bid Strategy Tracker

A performance dashboard for a (simulated) ad marketplace: publisher traffic, **Pub TAC** (traffic acquisition cost), revenue and margin, broken down by bidding strategy.

Built with **React 18 · TypeScript · Vite · Tailwind CSS 4 · Redux Toolkit + RTK Query · Chart.js · TanStack Table/Virtual**, with a serverless API on **Netlify Functions**.

> Demo project. All data is generated by the API, deterministic per query (same dates + filters → same numbers).

## Features

- **Filters drawer:** 9 multi-select filters with server-side search, select all and clear. Sub ID depends on the chosen publishers. Edits are a draft until **Apply**, and applied filters show as removable chips.
- **Date range:** presets (Today, 7/30/90 days, This month, 12 months) plus a validated custom range.
- **Shareable URLs:** dates, filters, tab and chart metrics are kept in the query string.
- **Summary tab:**
  - KPI cards with change against the previous period.
  - Stacked area chart: additive metrics are stacked, ratios are drawn as lines. An optional compare metric sits on a second axis.
  - Strategy tree legend with show/hide toggles.
- **Performance tree table:** expand/collapse, sorting, sticky header and first column, column visibility, CSV export.
- **Strategy Data tab:**
  - Any strategy, daily/weekly/monthly or by country.
  - Server-side sorting and pagination, with a totals row.
  - The "All rows" view is virtualised.
- **Bucket Analysis tab:** donut charts per metric with a fullscreen view.
- **Help drawer:** metrics glossary, drill-down structure, FAQs.
- **General:** light/dark theme, responsive layout, keyboard-friendly tabs and dialogs, loading, empty and error states with retry.

## Architecture

```
server/                  shared, framework-free API code (TypeScript)
  handler.ts             request router: /api/meta, /filters/:key, /summary, /performance, /strategy-data, /buckets
  data.ts                seeded data generation + aggregation
  dimensions.ts          publishers, sub IDs, advertisers… with traffic weights
  strategies.ts          bidding strategy tree (also used by the UI)
  types.ts               response types shared with the React app
netlify/functions/api.ts Netlify Function wrapping server/handler.ts  →  /api/*
src/
  app/                   Redux store, RTK Query API slice, URL <-> state sync
  features/              filters, dashboard (tabs), summary, strategy, buckets, help
  components/            layout, shared UI (Drawer, Modal, Segmented, states), icons
  context/ThemeContext   light/dark theme
  utils/                 metric definitions, formatting, dates, CSV, tree helpers
```

**State management**
- **RTK Query** handles all server data: caching, request de-duplication, loading and error state, prefetching.
- **Redux slices** hold the filters, date range and view settings that many components share.
- **Context** holds the theme, which is app-wide, changes rarely and has nothing to do with dashboard data.

**API in development:** `vite.config.ts` mounts the same `server/handler.ts` as middleware, so `npm run dev` serves the UI and the API together with no Netlify CLI. In production, Netlify serves `/api/*` from the function.

**Performance, applied where it pays off**
- Code-splitting per tab and per drawer, with tabs and their data **prefetched on hover**.
- RTK Query caching: going back to a previous filter or tab is instant.
- Server-side search, sorting, pagination and aggregation, so the browser receives only what it renders.
- Row virtualisation only for the large "All rows" table.
- Debounced filter search.
- Memoised chart datasets and table columns.
- Chart.js tree-shaken to the parts used, and animations off for long ranges.
- Long-term caching of hashed assets (`netlify.toml`) and short CDN caching of API responses.

## Deploy (GitHub + Netlify)

1. Push this folder to a new GitHub repository.
2. In Netlify: **Add new site → Import an existing project → GitHub →** pick the repo.
3. The settings come from `netlify.toml` (build `npm run build`, publish `dist`, functions `netlify/functions`). Click **Deploy**.

The API deploys with the site; nothing else is needed.

## API

| Endpoint | Description |
|---|---|
| `GET /api/meta` | Server time, last processed hour, allowed date range |
| `GET /api/filters/:key?search=&publishers=` | Options for a filter (`subId` requires `publishers`) |
| `GET /api/summary?from&to&<filters>` | Daily raw metrics per strategy node |
| `GET /api/performance?from&to&<filters>` | Strategy tree with totals |
| `GET /api/strategy-data?from&to&strategy&granularity&view&sort&dir&page&pageSize&<filters>` | Paginated table data |
| `GET /api/buckets?from&to&<filters>` | Smart-bidding bucket totals |

Filters are passed as comma-separated ids, for example `publisher=pub-1,pub-3&country=IE`. Dates are `YYYY-MM-DD` (UTC), up to 12 months back.
